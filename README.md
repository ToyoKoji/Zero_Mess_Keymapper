# Zero Mess Keymapper

ZMKファームウェアのキー配置を、ブラウザ上で視覚的に編集するためのエディタです。
インストール不要・単一HTMLファイルで動作し、**ある利用環境で作った配置を、別の配列・別のOS向けに双方向で自動変換**できます（US⇄JIS、Windows⇄macOS など）。

名前は **ZMK** のバクロニム。「配列のこんがらがり（mess）をゼロにする」という狙いを表しています。

👉 **[エディタを開く](https://ToyoKoji.github.io/Zero_Mess_Keymapper/)**

[English README](./README.en.md)

## これは何のためのツール?

ZMKのキー配置は `.keymap` というテキストファイルで記述しますが、記号の配置を考えるのも、レイヤーを行き来しながら全体を把握するのも、テキストだけでは骨が折れます。このツールは、実際のキーボードの形をした盤面をクリックしながら配置を組み立て、そのまま `.keymap` として書き出せるようにするものです。

### 「記号がズレる」問題を解決します

ZMKが送るのはキーの**位置**の信号で、そこから文字への変換はOSに委ねられます。そのためUS配列を前提に組んだ配置は、OSがJIS配列と認識した途端に記号が総崩れになります（`@` を押したはずが `"` になる、など）。

このツールの**配列変換**は、ある配列で組んだ配置を「別の配列でも見た目どおりの記号が入力される」キーコードへ自動変換します。**変換は双方向**で、US→JIS も JIS→US も同じように行えます。UK・ドイツ語との間も、どの組み合わせでも変換できます。Shiftの有無で記号が変わるキー（`'` と `"` など）には mod-morph を自動生成して対応します。

### OSごとの操作感も揃えられます

**OS変換**は、OSごとに異なるショートカットを**双方向に**変換します（`Ctrl+C` ⇄ `Cmd+C`、`Home` ⇄ `Cmd+←`、`Alt+Tab` ⇄ `⌘Tab` など）。会社ではWindows、自宅ではMac、外ではiPadというように機種をまたいでも、指の動きを変えずに済みます。

修飾キーの呼び名も利用環境のOSに合わせて表示が変わります（Windows は Alt / Win、macOS・iPadOS は ⌥ / ⌘）。

### 一つの設計を、すべての利用環境へ

このツールの中心にあるのは **「利用環境」** という考え方です。

```
利用環境 ＝ キーボード配列（OSの設定） × OS
```

例えば「会社PC = JIS × Windows」「自宅Mac = US × macOS」「iPad = US × iOS」。

利用環境ごとにレイヤーのまとまりを作り、**ひとつをベースとして設計**したら、残りは **「＋ 利用環境」から作るだけ**です。コピー元を指定すれば、その配置を変換したものが最初から入った状態で作られます。ベースを直したあとは「⇆ 利用環境間の同期」で追従させます。実機では切り替えキーで利用環境を移るので、**どの機種でも指の動きが変わりません**。

対応する配列は **US (ANSI) / JIS (日本語) / UK (ISO) / ドイツ語 (QWERTZ)**、OSは Windows / macOS / Linux / iOS / Android です。

変換の対象は「同じQWERTY系だが**記号の位置とShiftの挙動が違う**言語配列」に絞っています。Dvorak のように配置思想そのものが違う配列は、変換しても「同じ操作感」にはならないため対象外です。

ショートカットの体系は実質2系統（Ctrl系: Windows・Linux・Android / Cmd系: macOS・iPadOS）なので、この2つの間だけを変換します。同じ系統どうし（Windows→Linux など）では変換は起きず、キーコードの対応差だけを「OS互換チェック」が扱います。

**利用環境が1つだけなら、これらの機能は表示されません。** ふつうのキーマップエディタとして使えます。

## 主な機能

**キー配置の編集**

- 実機と同じ形の盤面をクリックして割り当て
- キーには「実際に入力される文字」を表示（利用環境の配列に応じて変化）
- 修飾キーの呼び名も**利用環境のOSに合わせて表示**（Windows は Alt / Win、macOS・iPadOS は ⌥ / ⌘）
- ドラッグ&ドロップで入れ替え・コピー、Undo/Redo（Ctrl+Z）

**利用環境ごとのレイヤー管理**

- レイヤーを利用環境（配列 × OS）ごとに整理。配列とOSは「設定なし」も選べます
- 利用環境単位の並べ替え・色分け。レイヤー番号と参照は自動で追従
- **利用環境の追加はウィザードで1回** — 名前・配列・OS・コピー元を指定すると、変換済みのレイヤー一式ができます
- **設定はレイヤー一覧で確認・変更** — 各利用環境の右に「JIS × Windows」のように表示され、クリックでその場で変更できます
- **利用環境切り替えキーの配置** — 実機で利用環境を移るキーを盤面から配置（Bluetooth連動は任意）
- **レイヤー順序の点検** — 呼び出しても無視されるレイヤーを検出し、ワンクリックで修正

**ZMKの機能に対応**

Combo / Mod-Morph / Tap-Dance / Macro / Conditional Layer / カスタムHold-Tap（ホームロウ修飾のキー位置条件つき） / Hold-Tap・Sticky Keyの全体調整 / トラックボール（PMW3610）

**支援機能**

- 書き出し前の整合性チェック（存在しないレイヤーへの参照・未定義ビヘイビアの検出）
- **OS互換チェック** — 使用するOSで反応しないキーコード（`K_MUTE`、変換 / 無変換など）を検出し、代替キーへ一括置換。Windows / macOS / Linux / iOS / Android に対応
- **コンボ・マクロ・tap-dance の利用環境別対応** — これらは複数の利用環境から共通で呼ばれるため、記号を出す定義は配列の違う利用環境で別の記号になります。検出して利用環境ごとに分割できます（参照元のレイヤーも自動で差し替え）
- 全設定のJSONバックアップ・復元
- 印刷用チートシートの出力
- キーテスター、ダーク/ライトテーマ、日本語 / English の表示切り替え
- GitHub連携（リポジトリから直接読み込み・コミット）

**他のキーボードにも対応**

代表的なキーボードを**内蔵**しています。「☰ メニュー → キーボード」から選ぶだけで使えます。

| プロファイル | キー数 |
|---|---|
| **HHKB（英字）** ← 既定 | 60 |
| roBa（トラックボール搭載） | 43 |
| Corne（6列 / crkbd） | 42 |
| Corne（5列） | 36 |
| Lily58 | 58 |
| Sofle | 60 |
| 格子 4×10 / 4×12 / 5×12 | 40 / 48 / 60 |

**一覧にない機種は、GitHubから探せます。** 「レイアウトを探す」にリポジトリを指定すると、物理レイアウトの定義を集めて一覧にします。既定の `zmkfirmware/zmk` なら **TKL・60%/65%/75%（ANSI / ISO / HHKB）・各種テンキー・Kyria・Corne・Sofle など60種類以上**が見つかります。自分の zmk-config を指定することもできます。

手元のファイル（`key_physical_attrs` を含む `.dtsi` / `.overlay`）を読み込む方法と、キー数を指定して簡易グリッドを作る方法も残しています。

**キーの大きさも変えられます。** 2Uのバックスペースや6.25Uのスペースなど、1Uでないキーに合わせて盤面を整えられます（「形を編集」）。大きさを変えると同じ行の後ろのキーが自動でずれ、重なりがあれば知らせます。キーの割り当ては変わりません。

> 内蔵プロファイルの座標は [ZMK公式リポジトリ](https://github.com/zmkfirmware/zmk/tree/main/app/dts/layouts) の物理レイアウト定義をそのまま取り込んでいます。

## 使い方

### `.keymap` ファイルについて

ZMKでは、キー配置を `.keymap` というテキストファイルに書きます。これは**設計図**であり、そのままキーボードに入れられるものではありません。GitHub上でビルドして、キーボードが読める `.uf2` に変換する必要があります。

このツールは設計図の**編集**を担当し、ビルドはGitHubが行います（無料・自動）。ブラウザだけでビルドすることは技術的にできないため、この分担はどのZMK用エディタでも共通です。

### 基本の流れ

1. エディタを開く（初期状態は roBa のデフォルト配置です）
2. **☰ メニュー → 読み込み** で、お使いの `.keymap` を読み込む
3. 盤面をクリックして編集
4. **.keymap書き出し** でファイルを保存（書き出し後、次の手順が画面に表示されます）
5. zmk-configリポジトリの `config/○○.keymap` に上書きしてコミット
6. GitHub Actions → 実行項目 → ページ最下部の **Artifacts** から firmware をダウンロード
7. zip内の `.uf2` を、ブートローダーモードのキーボードにコピー

### GitHub連携を使う場合（4〜5の短縮）

**☰ メニュー → GitHub連携** から、リポジトリの読み込みとコミットをブラウザ内で完結できます。

準備として、GitHubで **Fine-grained personal access token** を作成してください。

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens**
2. **Repository access** で対象のzmk-configリポジトリを選択
3. **Repository permissions → Contents** を **Read and write** に設定

> **トークンの取り扱いについて**
> 入力したトークンはお使いのブラウザ内にのみ保存され（保存するかは選択できます）、GitHub API以外へ送信されることはありません。共用のPCでは「このブラウザに保存」のチェックを外してご利用ください。

### 困ったときは

画面右上の **? ヘルプ** に、操作方法・キー表示の見かた・ZMKの機能解説をまとめています。各設定項目の **?** マークにも個別の説明があります。

## ZMK Studio との使い分け

ZMKには [ZMK Studio](https://zmk.studio/) という公式ツールがあり、キーボードをUSB接続してビルドなしでキー配置を変更できます。手軽さでは Studio が上です。

ただし Studio は「**ファームウェアに最初から入っている動作しか割り当てられない**」という制約があり、新しい動作の定義はできません（ZMK公式が「対応予定なし」と明記）。

本ツールの **US⇄JIS変換**は、まさにその「新しい動作の定義」（mod-morph の自動生成）を行うため、Studioでは実現できません。Combo・Conditional Layer・Macro の詳細設定も Studio では未対応です。

| | ZMK Studio | Zero Mess Keymapper |
|---|---|---|
| ビルド | 不要（即反映） | 必要（GitHub Actions） |
| キーの入れ替え | ⭕ | ⭕ |
| 新しい動作の定義（mod-morph等） | ❌ | ⭕ |
| US⇄JIS変換 | ❌ | ⭕ |
| Combo / Conditional Layer | 未対応 | ⭕ |
| Macro の詳細設定 | 未対応 | ⭕ |

配置を少し入れ替えるだけなら Studio、記号配置・JIS対応・Combo・Macro を設計するなら本ツール、という関係です。

## 開発者向け

単一のHTMLファイルで、外部ライブラリへの依存はありません。

```
index.html    本体（core層 = DOM非依存ロジック / UI層）
tests.js      自動テストスイート
ui-tests.js   画面を実際に動かすテスト（jsdom）
```

テストの実行:

```bash
node tests.js            # 1209項目（うち画面の動作141項目）
npm install jsdom        # 画面の動作テストに必要（無い場合はその部分を省略）
```

`tests.js` は core層の計算とHTMLの構造を検査し、続けて `ui-tests.js` を呼び出して**実際にボタンを押したときの動作**を確かめます。

検証している主なもの:

- パース・生成の往復一致、各種変換の可逆性（全5配列の全キー）
- 状態の保存・復元（Undo履歴・ブラウザ保存・バックアップの取りこぼし検出）
- レイヤーの複製・削除・移動にともなう参照の追従
- OS互換テーブルの公式資料との一致
- 壊れたファイルを読ませたときの耐性
- 画面部品の不変条件（参照しているidの実在、重複なし）

変更を加えた際は実行してください。

設計の概要はHTMLファイル冒頭のコメントに記載しています。
