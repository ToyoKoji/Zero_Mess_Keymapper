ヘルプ

ZMKファームウェア用のキーマップエディタです。ブラウザだけで動作し、編集内容は自動で保存されます。

名前の Zero Mess Keymapper は ZMK のバクロニムで、「配列のこんがらがりをゼロにする」という狙いを表しています。
考え方 — 「環境」ごとにレイヤーを持つ
このツールでは、使う場面のことを「環境」と呼びます。環境は キーボード配列（OSの設定）× OS の組み合わせです。

例: 「会社PC = JIS × Windows」「自宅Mac = US × macOS」「iPad = US × iOS」

環境ごとにレイヤーのまとまりを作り、ひとつをベースとして設計し、残りは「⇆ 環境間の同期」で自動生成します。実機では、共有レイヤーに置いた切り替えキー（&to）で環境を切り替えます。こうすると、どの機種でも指の動きを変えずに済みます。

環境が1つだけなら、これらの機能は表示されません。ふつうのキーマップエディタとして使えます。

各環境はレイヤー一式をそれぞれ持つのが基本です。マウスやBluetoothの層も環境ごとに複製されますが、同期はキー単位で差分を見るため、Bluetoothキーのように環境で変わらないものは自動的にそのまま保たれます。テンキー層にBluetoothキーを混ぜても問題ありません。

レイヤー数を節約したい場合は、配列とOSをどちらも「設定なし」にした環境を作ると変換の対象外になるので、どの環境からも呼び出す共通の層として使えます。その場合はすべての環境より後ろに置いてください（理由は「このツールの機能 → レイヤー順序の点検」を参照）。

.keymap ファイルとは
ZMKでは、キー配置を .keymap というテキストファイルに書きます。これは設計図であって、そのままキーボードに入れられるものではありません。GitHub上でビルド（コンパイル）して、キーボードが読める .uf2 というファームウェアに変換する必要があります。

このツールは設計図の編集を担当します。ビルドはGitHubが行います（無料・自動）。ブラウザだけでビルドすることは技術的にできないため、この分担はどのZMK用エディタでも共通です。
キーボードへの反映
1「.keymap書き出し」でファイルを保存します
2GitHubリポジトリの config/roBa.keymap に上書きします
3GitHub Actionsが自動でビルドします
4できた .uf2 をキーボードに書き込みます
トラックボールのセンサー設定(速度など)のみ、config/roBa_R.conf への反映が別途必要です。
「☰ メニュー → GitHub連携」を使うと、1〜2の手順(ダウンロードと上書き)をブラウザから直接コミットで済ませられます。
ZMK Studio との違い
ZMKには ZMK Studio という公式ツールがあり、キーボードをUSB接続してビルドなしでその場でキー配置を変更できます。手軽さでは Studio が上です。

ただし Studio には「ファームウェアに最初から入っている動作しか割り当てられない」という制約があります。新しい動作を定義することはできません（ZMK公式が「対応予定なし」と明記しています）。

このツールの US⇄JIS変換は、まさにその「新しい動作の定義」（mod-morph の自動生成）を行うため、Studioでは実現できません。Combo・Conditional Layer・Macro の詳細設定も Studio では未対応です。

使い分け: 配置を少し入れ替えるだけなら Studio、記号の配置・JIS対応・Combo・Macro などを設計するならこのツール、という関係です。なお Studio を使い始めると .keymap の変更が反映されなくなるため、併用する場合は Studio 側で「Restore Stock Settings」が必要です。

ZMKとは
ZMKは自作キーボード向けのオープンソースファームウェアです。Bluetooth接続と低消費電力に強く、roBaのような無線分割キーボードで広く使われています。設定は .keymap というテキストファイルで行い、このツールはそのファイルを画面操作から生成します。

主な機能
レイヤー
キーボード全体の配置をまるごと切り替える「面」です。役立つ場面: 42キーしかなくても、数字・記号・ファンクションを別の面に置いて無理なく使えます。
透過(▽)と無効(✕)
▽は下で有効なレイヤーのキーをそのまま使い、✕は何も入力しません。役立つ場面: レイヤーで変えたいキーだけ定義して残りは▽にすると、管理が楽になります。
Conditional Layer(tri-layer)
指定したレイヤーがすべて同時にONのとき、別のレイヤーを自動でONにします。役立つ場面: 親指2キーの同時押しで、3つ目の設定用レイヤーを呼び出す定番テクニックです。
Hold-Tap(&mt / <)
短く押すと文字、押しっぱなしで修飾キーやレイヤーになる1キー2役の仕組みです。役立つ場面: ホームポジションの指の下に修飾キーを置けます(ホームロウモッド)。反応は「全体調整」で調整できます。独自のHold-Tap(キー位置条件つき)は「⇓ Hold-Tap」画面で作成できます。
Combo
複数キーの同時押しで別の動作を出します。役立つ場面: EscやTabのような使用頻度の低いキーを、独立キーなしで呼び出せます。
mod-morph
Shiftなどを押しているときだけ別のキーになります。役立つ場面: 「,」と「!」を1キーにまとめるなど、Shiftペアを自由に設計できます。US⇄JIS変換でも内部的に使われます。
tap-dance
短い間隔でのタップ回数によって動作が変わります。役立つ場面: 1回で再生/停止、2回で次の曲、のように関連機能を1キーにまとめられます。
Macro
キー操作の列を1キーで再生します。役立つ場面: 定型文の入力や、Ctrl+C→Ctrl+Vのような連続操作のワンキー化に使えます。
Sticky Key(SK)
押して離した後の「次の1キー」にだけ修飾が効きます。役立つ場面: 小さいキーボードで、Shiftを押さえたまま他のキーを押す同時押しを避けられます。
Caps Word
次の単語だけ自動で大文字になります。役立つ場面: MAX_SIZE のような定数名の入力に便利です。
Bluetooth
BT 0〜4で接続先を切り替えます。BOOTはファームウェア書き込みモードへの移行です。役立つ場面: PC・タブレットなど複数の機器をキー1つで切り替えられます。
US⇄JIS変換
OSのキーボード設定が「日本語(JIS)」のPCでは、US配列想定のキーマップだと記号の位置がズレます(例: @ のつもりが ")。この機能は、USグループの配置をJIS認識のOSでも見た目どおりの記号が入力されるキーコードへ変換し、JISグループへコピーします。

Shiftの有無で記号が変わるキー(' と " など)は、mod-morph(jis_*)を自動生成して対応します。この変換は「＋ 環境」または「⇆ 環境間の同期」から行います。環境に US と JIS の配列を設定しておけば、どちらの向きにも変換できます。実行前に対象キーの一覧で確認・選択でき、実機での切り替えキーは「⇥ 切り替えキーを配置」で用意できます。
環境切り替えキーの配置
実機で環境を切り替えるキーを、盤面から位置を選んで配置します。ZMKの &to（そのレイヤーへ移動し、他を解除する）を使います。

Bluetoothプロファイルの切り替えを併用するかは任意です。環境ごとに接続先の機器が違うならオンに、有線だけで使う場合や同じ機器で環境を使い分ける場合はオフのままにしてください（レイヤーの切り替えだけを行います）。

配置先のレイヤーはどこでも構いません。どの環境からも押せる場所を選んでください。補足: 電源を入れ直すと最初の環境（レイヤー0）に戻ります。いちばん使う環境を先頭に置いておくと扱いやすくなります。
レイヤー順序の点検
ZMKには「レイヤー0は常に有効」「番号が大きいレイヤーが優先」というルールがあります。そのため、あるレイヤーから自分より前（番号が小さい）レイヤーを呼び出しても無視されます。

「⇅ レイヤー順序を点検」は、実際にそうなっている呼び出しを見つけて表示し、ワンクリックで並べ替えられます（レイヤー番号と参照は自動調整）。あわせて、環境の最初のレイヤーにある透過（▽）も検出します。透過の位置ではレイヤー0＝最初の環境の割り当てが出てしまうためです。役立つ場面: 環境を切り替えたらマウス操作が効かなくなった、という不具合の原因がこれです。どの環境からも呼び出したいレイヤーは、すべての環境より後ろに置いてください。
グループ間変換（配列規格 / OS）
グループごとに配列規格（US・JIS・UK・ドイツ語・Dvorak）と対象OS（Windows・macOS・Linux）を指定でき、あるグループの配置をもう一方に合わせて作り直せます。配列とOSの両方が違う場合は同時に変換します。US⇄JIS変換もこの仕組みの一部です。役立つ場面: 3種類以上の環境を1つのキーボードで使い分けるとき、それぞれのグループを1回の操作で揃えられます。
Win⇄Mac変換
WindowsとmacOSでは、同じ操作でも押すキーが異なります（コピーは Ctrl+C と Cmd+C、行頭移動は Home と Cmd+← など）。変換元のグループを元に、もう一方のOS向けの配置をまとめて作れます。日本語入力の切替（変換/無変換 ⇄ かな/英数）にも対応します。役立つ場面: 会社ではWindows、自宅ではMacというように機種をまたぐとき、指の動きを変えずに済みます。US⇄JIS変換と同じく、実行前に差分を一覧で確認できます。
Shift入力トグル
そのレイヤーで、Shiftを押しながらの記号打ちを使うかを指定します。「有効」のレイヤーだけJIS変換でmod-morphを生成し、キー右上にShift面を表示します。ショートカットの修飾同時押しには影響しません。役立つ場面: ファンクション・マウス・Bluetooth用など記号打ちをしないレイヤーを「無効」にしておくと、不要なmod-morphが作られず、キーマップも表示もシンプルに保てます。
キーの表示はOSに合わせて変わります
同じキーコードでも呼び名はOSで違います。環境のOSを macOS か iPadOS にすると、盤面・チートシート・キー割り当て画面の表示が Mac の呼び方に変わります。キーコード自体は変わりません（表示だけの違いです）。

OSが「設定なし」の環境では、Windows/Linux と同じ表記（キーコード名に近い形）で表示します。
OSをまたぐときの修飾キー
ショートカットの体系はCtrl系（Windows / Linux / Android）とCmd系（macOS / iPadOS）の2つです。変換されるのは主修飾キーだけで、対応は次のとおりです。
Windows / LinuxmacOS / iPadOS扱い
Ctrl（LCTRL / LC()）Cmd（LGUI / LG()）相互に変換
Alt（LALT / LA()）Option（同じ LALT）変換しない（同じキー）
ShiftShift変換しない
Win（LGUI）—対応するキーがない（下記）
—Control（LCTRL）対応するキーがない（下記）
AltとOptionは同じキーです。ZMKではどちらも LALT で、押す位置も同じなので変換は不要です。ただし Alt+Tab（アプリ切替）と Alt+F4（終了）だけは、macOSでは ⌘Tab / ⌘Q にあたるため個別に変換します。

WinキーとmacOSのControlキーには相手がいません。 Ctrl と Cmd を入れ替える都合上、元からWinキーを使っていた位置は変換後のCmdと重なります。該当する位置があると変換時に注意を出すので、その位置だけ手で見直してください。
マクロ・tap-dance と環境
コンボと同じことが、マクロ・tap-dance・自作のmod-morphにも起こります。定義は1つなのに複数の環境のレイヤーから呼ばれるため、記号を出す定義は配列の違う環境で別の記号になります。各画面を開くと検出して知らせるので、「環境ごとに分ける」を押してください。定義が複製され、その環境のレイヤーの参照先も自動で差し替わります。変換で自動生成された mod-morph は、はじめから環境専用なので対象外です。
コンボと環境
ZMKのコンボは全レイヤーで動きます。そのため " のような記号を出すコンボは、配列の違う環境では別の記号が出てしまいます。「Combo」画面を開くと該当するコンボを検出して知らせるので、「環境ごとに分ける」を押してください。コンボが環境の数だけ複製され、それぞれに layers 指定と変換後の動作が入ります。Bluetoothやマウスなど、環境で変わらない動作のコンボは検出されません。
環境の設定を変える
レイヤー一覧の各環境の右にある設定チップ（例: JIS × Windows）をクリックすると、キーボード配列とOSをその場で変更できます。設定を変えても配置はそのままです。実際に変換するときは「⇆ 環境間の同期」を使ってください。
環境の追加
「＋ 環境」を押すと、名前・キーボード配列・OS・コピー元を1つの画面で指定できます。コピー元を選んでおけば、その配置を変換したものが入った状態で作られるので、あとから同期する必要はありません。以前は「グループを作る → レイヤーを増やす → 同期する」の3段階でしたが、1回で済むようになりました。
環境と「設定なし」
レイヤーは環境（キーボード配列 × OS）ごとにまとめて管理します。各環境はレイヤー一式をそれぞれ持つのが基本です。

配列とOSをどちらも「設定なし」にした環境は変換の対象外になります。これを利用すると、どの環境からも呼び出す共通のレイヤーとして使えます（その場合はすべての環境より後ろに置いてください）。ツール側で「共有レイヤー」という特別な種別は設けていません。

実のところ、完全に環境非依存なキーは &bt（Bluetooth切替）や &rgb_ug のようなキーボード内部で完結するものだけです。マウスのスクロールはmacOSの「ナチュラルスクロール」で向きが変わり、KP_EQUAL はWindowsで反応せず、F13以降はAndroidが非対応です。つまり「この層は環境非依存」と層単位で決めつけるのは無理があります。

そこで本ツールはキー単位で差分を見て同期します。テンキー層にBluetoothキーを混ぜても、Bluetoothキーはそのまま保たれ、環境で変わるキーだけが変換されます。書き出し時はグループ番号を含む名前で保存されるため、グループが違えば同じレイヤー名を使えます。グループ名の左のラベルには色が付き、ラベル横の●からいつでも変更できます(初期値: US=青、JIS=シアン、GENERAL=アンバー)。役立つ場面: US側とJIS側で対応するレイヤーに同じ名前を付けられるので、対応関係がひと目で分かります。
OS互換チェック
キーコードには、特定のOSだけが解釈しないものがあります。たとえばメディアキーは見た目が同じでも中身が2種類あり(K_MUTE と C_MUTE)、前者はWindowsとmacOSが解釈しないため押しても何も起きません。逆に C_STOP のようにWindowsだけ非対応のキーもあります。

「☰ メニュー → OS互換チェック」で使用するOSを選ぶと、そのOSで反応しないキーを一覧表示し、代替キーへ一括置換できます。補足: Linuxは最も対応範囲が広く、メディアキーはどちらの種類でも動作します。ただし SYSREQ や LOCKING_CAPS のような旧式のキー、INT7〜INT9・LANG6〜LANG9 は非対応です。判定はZMK公式のキーコード一覧に基づいています。
整合性チェック
書き出し・プレビュー時に、存在しないレイヤーへの参照や未定義ビヘイビアなどを自動で検査し、問題があれば一覧表示します。役立つ場面: ビルドしてから気付くミスを、書き出す前に発見できます。
バックアップ / 復元
全設定をJSONファイル1つで保存・完全復元できます。役立つ場面: ブラウザのデータ削除や別PCへの移行、配列の試行錯誤前の保険に。
チートシート
全レイヤー・コンボ・各種設定をまとめた印刷用HTMLを出力します(☰ メニュー)。役立つ場面: 覚えるまでの間、手元に置く配列表として使えます。
GitHub連携
「☰ メニュー → GitHub連携」でzmk-configリポジトリから直接keymapを読み込み、編集後そのままコミットできます。コミットするとGitHub Actionsのビルドが自動で始まります。役立つ場面: ファイルのダウンロードとアップロードが不要になり、編集からビルドまでブラウザだけで完結します。

準備: GitHubの Settings → Developer settings → Personal access tokens → Fine-grained tokens でトークンを作成し、対象リポジトリを選んで Repository permissions の Contents を「Read and write」に設定してください。トークンはこのブラウザにのみ保存され、通信先はGitHub APIだけです(共用PCでは「このブラウザに保存」のチェックを外してください)。
キーボードプロファイル
「☰ メニュー → キーボード」で編集対象のキーボードを管理します。ZMKの物理レイアウト定義(key_physical_attrs)を含むファイルを読み込むと盤面を自動で再現でき、roBa以外のキーボードも編集できます。役立つ場面: 複数のZMKキーボードを1つのツールで管理できます。
キーテスター
キーボードから実際に入力して、OSに届いたキーと修飾の状態を確認できます(「☰ メニュー」)。役立つ場面: ファームウェア書き込み後の動作確認や、JIS変換後に記号が正しく出るかのチェックに。
テーマ・表示言語
テーマ(自動 / ライト / ダーク)と表示言語(日本語 / English)を「表示切り替え」行で切り替えられます。
