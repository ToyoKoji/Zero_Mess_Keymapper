ヘルプ

ZMKファームウェア用のキーマップエディタです。ブラウザだけで動作し、編集内容は自動で保存されます。

名前の Zero Mess Keymapper は ZMK のバクロニムで、「配列のこんがらがりをゼロにする」という狙いを表しています。
できること
・盤面をクリックしてキー配置を編集
・Combo / Mod-Morph / Tap-Dance / Macro / トラックボールの設定
・US配列で作った配置を、JIS認識のOS用に自動変換(US⇄JIS変換)
・GitHubのzmk-configから直接読み込み・コミット
他のツールとの違い
このツールならでは
・US⇄JIS変換(Shiftペアのmod-morph自動生成を含む)
・Shift入力トグルと、実際に入力される文字でのキー表示
・レイヤーグループ(並べ替え・色分け・fw番号の自動追従)
・roBaのトラックボール(PMW3610)設定UI
・インストール不要。ブラウザだけで動き、オフラインでも使えます
できないこと
・キーボードへの直接書き込み(ZMK Studioのようなリアルタイム反映)。GitHub Actionsでのビルドが必要です
・roBa以外のキーボードへの対応(現時点)
・パラメータ付きの自作ビヘイビアの編集(壊さないよう、内容はそのまま保持します)
キーボードへの反映
1「.keymap書き出し」でファイルを保存します
2GitHubリポジトリの config/roBa.keymap に上書きします
3GitHub Actionsが自動でビルドします
4できた .uf2 をキーボードに書き込みます
トラックボールのセンサー設定(速度など)のみ、config/roBa_R.conf への反映が別途必要です。
「☰ メニュー → GitHub連携」を使うと、1〜2の手順(ダウンロードと上書き)をブラウザから直接コミットで済ませられます。

ZMKとは
ZMKは自作キーボード向けのオープンソースファームウェアです。Bluetooth接続と低消費電力に強く、roBaのような無線分割キーボードで広く使われています。設定は .keymap というテキストファイルで行い、このツールはそのファイルを画面操作から生成します。

ZMK公式ドキュメント / キーコード一覧 / ビヘイビア一覧 / roBaリポジトリ
主な機能
レイヤー
キーボード全体の配置をまるごと切り替える「面」です。役立つ場面: 42キーしかなくても、数字・記号・ファンクションを別の面に置いて無理なく使えます。
透過(▽)と無効(✕)
▽は下で有効なレイヤーのキーをそのまま使い、✕は何も入力しません。役立つ場面: レイヤーで変えたいキーだけ定義して残りは▽にすると、管理が楽になります。
Conditional Layer(tri-layer)
指定したレイヤーがすべて同時にONのとき、別のレイヤーを自動でONにします。役立つ場面: 親指2キーの同時押しで、3つ目の設定用レイヤーを呼び出す定番テクニックです。
Hold-Tap(&mt / <)
短く押すと文字、押しっぱなしで修飾キーやレイヤーになる1キー2役の仕組みです。役立つ場面: ホームポジションの指の下に修飾キーを置けます(ホームロウモッド)。反応は「全体調整」で調整できます。独自のHold-Tap(キー位置条件つき)は「⇓ Hold-Tap」画面で作成できます。
Combo
複数キーの同時押しで別の動作を出します。役立つ場面: EscやTabのような使用頻度の低いキーを、独立キーなしで呼び出せます。
mod-morph
Shiftなどを押しているときだけ別のキーになります。役立つ場面: 「,」と「!」を1キーにまとめるなど、Shiftペアを自由に設計できます。US⇄JIS変換でも内部的に使われます。
tap-dance
短い間隔でのタップ回数によって動作が変わります。役立つ場面: 1回で再生/停止、2回で次の曲、のように関連機能を1キーにまとめられます。
Macro
キー操作の列を1キーで再生します。役立つ場面: 定型文の入力や、Ctrl+C→Ctrl+Vのような連続操作のワンキー化に使えます。
Sticky Key(SK)
押して離した後の「次の1キー」にだけ修飾が効きます。役立つ場面: 小さいキーボードで、Shiftを押さえたまま他のキーを押す同時押しを避けられます。
Caps Word
次の単語だけ自動で大文字になります。役立つ場面: MAX_SIZE のような定数名の入力に便利です。
Bluetooth
BT 0〜4で接続先を切り替えます。BOOTはファームウェア書き込みモードへの移行です。役立つ場面: PC・タブレットなど複数の機器をキー1つで切り替えられます。
US⇄JIS変換
OSのキーボード設定が「日本語(JIS)」のPCでは、US配列想定のキーマップだと記号の位置がズレます(例: @ のつもりが ")。この機能は、USグループの配置をJIS認識のOSでも見た目どおりの記号が入力されるキーコードへ変換し、JISグループへコピーします。

Shiftの有無で記号が変わるキー(' と " など)は、mod-morph(jis_*)を自動生成して対応します。変換ボタンは差異があるときだけ有効になり(件数表示)、実行前に対象キーの一覧で確認・選択できます。逆方向(JIS→US)も可能です。US/JISの切り替えは &to をキーに割り当ててください(実番号は「№」で確認できます)。
Shift入力トグル
そのレイヤーで、Shiftを押しながらの記号打ちを使うかを指定します。「有効」のレイヤーだけJIS変換でmod-morphを生成し、キー右上にShift面を表示します。ショートカットの修飾同時押しには影響しません。役立つ場面: ファンクション・マウス・Bluetooth用など記号打ちをしないレイヤーを「無効」にしておくと、不要なmod-morphが作られず、キーマップも表示もシンプルに保てます。
レイヤーグループ
US / GENERAL(共有) / JIS の3グループでレイヤーを管理します(追加も可能)。書き出し時はグループ番号を含む名前で保存されるため、グループが違えば同じレイヤー名を使えます。グループ名の左のラベルには色が付き、ラベル横の●からいつでも変更できます(初期値: US=青、JIS=シアン、GENERAL=アンバー)。役立つ場面: US側とJIS側で対応するレイヤーに同じ名前を付けられるので、対応関係がひと目で分かります。
Windows互換チェック
メディアキーには、見た目は同じでも中身が異なる2種類のキーコードがあります(K_MUTE と C_MUTE など)。前者はWindowsが解釈しないため押しても何も起きません。「☰ メニュー → Windows互換チェック」で該当箇所を検出し、全OSで動作するキーコードへ一括置換できます。役立つ場面: ミュートや再生停止が効かない原因の多くがこれです。書き出し時の整合性チェックでも自動で警告します。
整合性チェック
書き出し・プレビュー時に、存在しないレイヤーへの参照や未定義ビヘイビアなどを自動で検査し、問題があれば一覧表示します。役立つ場面: ビルドしてから気付くミスを、書き出す前に発見できます。
バックアップ / 復元
全設定をJSONファイル1つで保存・完全復元できます。役立つ場面: ブラウザのデータ削除や別PCへの移行、配列の試行錯誤前の保険に。
チートシート
全レイヤー・コンボ・各種設定をまとめた印刷用HTMLを出力します(☰ メニュー)。役立つ場面: 覚えるまでの間、手元に置く配列表として使えます。
GitHub連携
「☰ メニュー → GitHub連携」でzmk-configリポジトリから直接keymapを読み込み、編集後そのままコミットできます。コミットするとGitHub Actionsのビルドが自動で始まります。役立つ場面: ファイルのダウンロードとアップロードが不要になり、編集からビルドまでブラウザだけで完結します。

準備: GitHubの Settings → Developer settings → Personal access tokens → Fine-grained tokens でトークンを作成し、対象リポジトリを選んで Repository permissions の Contents を「Read and write」に設定してください。トークンはこのブラウザにのみ保存され、通信先はGitHub APIだけです(共用PCでは「このブラウザに保存」のチェックを外してください)。
キーボードプロファイル
「☰ メニュー → キーボード」で編集対象のキーボードを管理します。ZMKの物理レイアウト定義(key_physical_attrs)を含むファイルを読み込むと盤面を自動で再現でき、roBa以外のキーボードも編集できます。役立つ場面: 複数のZMKキーボードを1つのツールで管理できます。
キーテスター
キーボードから実際に入力して、OSに届いたキーと修飾の状態を確認できます(「☰ メニュー」)。役立つ場面: ファームウェア書き込み後の動作確認や、JIS変換後に記号が正しく出るかのチェックに。
テーマ
自動(OSの設定に追従)/ ライト / ダークを「表示切り替え」行で切り替えられます。
